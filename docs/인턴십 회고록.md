# Garela Community 프로젝트 회고

**㈜메비츠 현장실습(인턴십) · 2024.06.24 ~ 2024.07.19 (4주)**

## 어쩌다 이 프로젝트를 하게 됐나

4주짜리 현장실습이었는데, 회사의 실무에 바로 투입되는 형태는 아니었습니다. 대표님께서 개인 프로젝트 과제를 내주셨고, 취지는 "풀스택 개발 프로세스(서비스의 생애주기)를 처음부터 끝까지 경험해보라"는 것이었습니다. 주제도 자유롭게 정하기보다는 가이드가 있었습니다 — 지금 운영 중인 게시판 서비스들의 문제점이나 아쉬운 점을 스스로 생각해보고, 이를 개선하는 아이디어로 게시판을 기획하고 만들어보라는 과제였습니다.

그렇게 나온 것이 **템플릿 기반 게시글 작성이 가능한 커뮤니티, Garela Community**입니다. "글을 잘 쓰는 사람의 구조를 템플릿으로 가져와서 누구나 쉽게 좋은 글을 쓸 수 있게 하자"는 것이 기획 의도였습니다.

## 1~2주차: 게시판의 기본기부터

첫 1~2주는 게시판의 기본적인 CRUD, 로그인/회원가입 구현이 요구사항이었습니다. React + TypeScript + Recoil + React Router + Styled Components로 프론트를, Node.js/Express로 백엔드를 잡고 하나씩 구현했습니다.

## 3~4주차: 챗봇, 그리고 "벡터 DB"라는 개념

3~4주차는 서비스에 챗봇을 붙이는 것이 목표였습니다. 이때 대표님께서 벡터 DB라는 개념을 소개해주셨고, LangChain 프레임워크를 활용해 게시판에 쌓인 데이터를 기반으로 답변하는 챗봇을 만들어보라고 하셨습니다.

실제로 구현한 것은 벡터 DB나 임베딩 기반 유사도 검색이 아니었습니다. 4주라는 기간과 당시 역량을 고려해, 질문에서 키워드를 추출하고 그 키워드가 포함된 게시글을 SQL로 필터링해 컨텍스트로 넘기는 방식으로 구현 범위를 좁혔습니다. 소개받은 개념과 실제 구현 사이에는 거리가 있었지만, 짧은 기간 안에 "게시글 데이터를 참고해 답변하는 챗봇"이라는 요구사항 자체는 완성했습니다.

LangChain 연동은 별도 Python 프로세스로 띄워 처리했습니다. 뚜렷한 기술적 근거가 있었던 것은 아니고, 당시 JS보다 Python 쪽에 LangChain 관련 자료가 더 많다고 느껴 선택한 실용적인 판단에 가까웠습니다. 그 결과 서비스가 Node.js API 서버와 Python AI 서버, 두 프로세스로 나뉘어 로컬에서 함께 띄워야 하는 번거로움이 있었습니다.

## 트러블슈팅: 에디터 이미지가 저장되지 않던 문제

Quill 에디터를 사용했는데, 이미지를 첨부하면 기본 동작으로 이미지가 Base64 문자열로 인코딩되어 본문에 그대로 삽입됐습니다. 문제는 이 상태로 저장하면 DB 저장이 되지 않았다는 것이었습니다.

원인은 게시글 본문 컬럼이 MySQL `TEXT` 타입(최대 65,535바이트)이었는데, 이미지를 Base64로 인코딩하면 원본보다 크기가 커지면서(약 1.33배) 이 한도를 쉽게 초과했기 때문이었습니다. 컬럼을 `LONGTEXT`로 늘리는 방법도 있었지만, 이미지가 늘어나면 다시 부딪힐 임시방편이라 판단해 이미지를 본문과 분리하는 방향으로 해결했습니다.

Quill의 이미지 삽입 핸들러를 오버라이드해, 이미지를 첨부하면 곧바로 서버로 업로드하고 → 서버는 해당 이미지를 AWS S3에 업로드한 뒤 → 반환된 URL을 본문에 다시 삽입하는 구조로 변경했습니다. 다만 게시글 삭제 시 S3에 업로드된 이미지까지 함께 정리하는 로직은 구현하지 않았습니다 — 4주라는 기간 안에서는 해당 부분을 스코프 아웃했습니다.

*(자세한 구현 코드는 [Quill 에디터 이미지 Base64 저장 한계 → S3 URL 참조 전환](troubleshooting/01-quill-image-base64-to-s3.md) 문서에, 챗봇 구현 상세는 [AI 챗봇: 벡터 DB 대신 키워드 매칭으로 구현 범위를 좁힌 이유](troubleshooting/02-chatbot-keyword-vs-vector-db.md) 문서에 정리되어 있습니다.)*

## 아쉬웠던 점

인증 구현에는 아쉬운 점이 있습니다. JWT 기반 인증을 구현하긴 했지만, 이메일 인증이나 OAuth 연동은 하지 않았고 액세스 토큰만 발급해 사용했습니다. 4주라는 기간 안에서 "우선 로그인이 동작하게 만든다"는 우선순위였던 것으로 보입니다.

이번에 문서를 정리하면서 코드를 다시 확인해보니, `package.json`에 설치돼 있던 `sequelize`가 실제로는 코드 어디에서도 쓰이지 않고 있었습니다. DB 접근은 `mysql2`로 raw 커넥션을 열어 SQL을 직접 실행하는 방식이었습니다. `@langchain/core`(JS)와 구버전 `aws-sdk`도 마찬가지로 설치만 되어 있고 실제로는 사용되지 않는 의존성이었습니다.

## 남은 것들

근무는 회사로 출근하기도 했지만, 개인 프로젝트인 만큼 학교 건물이나 근처 카페에서 작업해도 된다는 편의를 받았습니다.

대표님과는 첫 미팅, 중간 점검, 최종 미팅으로 세 차례 만났고, 그때마다 프로젝트 피드백뿐 아니라 커리어 로드맵과 LangChain 같은 기술에 대한 조언도 받을 수 있었습니다. 벡터 DB라는 개념을 처음 접한 것과, 짧은 기간 안에 기획부터 구현까지 한 사이클을 단독으로 진행해본 것이 이 인턴십에서 얻은 경험이었습니다.
